RAG — Retrieval & Generation Flow
1. User QueryPregunta del prospecto sobre servicios, industria, metodología, casos, ecommerce, IA, medición, etc.
↓
2. Query ProcessingNormalización, detección de intención, filtros de metadata, reformulación opcional.
↓
3A. Semantic SearchEmbedding query → pgvector → HNSW candidates.
3B. Keyword SearchPostgreSQL Full Text Search → GIN candidates.
↓ merge ↓
4. Reciprocal Rank FusionCombina resultados semánticos y léxicos; top 15–20 candidatos.
↓
5. RerankerReordena candidatos por relevancia real; selecciona top 5–8.
↓
6. Context BuilderDeduplicación, límites de tokens, metadata, source IDs y contexto final.
↓
7. ClaudeSystem + conversation summary + recent turns + retrieved context + current question.
↓
8. Grounded AnswerRespuesta + fuentes + acciones sugeridas + señales de lead.

Technology Decisions
Frontend / BFF
TanStack Start, React 19, TypeScript, Tailwind CSS, Bun, Nitro node-server.
AI Backend
Python 3.12+, FastAPI, Pydantic v2, httpx / Anthropic SDK, SSE streaming.
LLM
Anthropic Claude como principal; interfaz de proveedor para fallback sin acoplar el agente al vendor.
RAG
Supabase PostgreSQL + pgvector, HNSW, PostgreSQL FTS + GIN, hybrid retrieval + RRF, reranking.
Data
Supabase PostgreSQL para conversations, messages, leads, knowledge_documents, knowledge_chunks y telemetry metadata.
Storage
Supabase Storage para fuentes originales y artefactos de conocimiento.
Observability
Langfuse para LLM/RAG traces, Sentry para errores y OpenTelemetry para trazas técnicas.
Deploy
Render Web Services + Background Worker. GitHub como fuente de verdad y CI/CD.
Security
Secrets solo en Render/Supabase, RLS, CORS estricto, input validation, rate limiting, request IDs y sanitización.
Testing
Pytest + Vitest, contract tests, golden RAG dataset, retrieval metrics y end-to-end chat tests.
